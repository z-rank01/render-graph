### 1.3 分支预测 / SIMD 友好度：**差**
- variant 分发使每个事件消费循环带不可预测数据相关分支（image/buffer 交错时预测率骤降）。
- O(n²) 内层循环 + continue 级联（`append_access`、DAG 配对、aliasing）污染分支历史表，且无法矢量化。
- 嵌套 vector（DAG、prologues、batch）与 `unordered_map`/`priority_queue` 是节点跳转 + 指针追逐，prefetch 失效。
- 没有任何批量掩码处理；所有过滤都是 `continue` 跳过，没有任何"全部算完再掩码写回"的 SIMD 友好段。
- 缓解因素（要诚实说明）：plan cache 使稳态帧 compile 调用为零，当前这些代价只在首帧/热重载/大 graph 时显形。本轮的动机是风格宪法一致性 + 大场景扩展性，而非已观测到的稳态热点。
### 1.4 函数式低副作用 / 惰性创建：**方向对，约束弱**
- 符合：compile 只产 desc/requirements 行，物理资源由后端一次性批量分配；cull 后无生命周期资源零分配；cache 命中零编译。
- 不符合：`compiler_state`（`system.h:38-47`）是全字段可写的上帝对象，阶段纯度无强制——`cull_passes` 回写 `passes[p].active` 并 `erase_if` 输入事件流；`append_access` 在阶段内原地合并累加。阶段间不是"输入表 → 新表"，而是共享状态原地变异。
### 1.5 依赖方向：**单向但未收窄**
- 九阶段严格顺序、无回读（好）。
- 但数据不"变窄"：被 cull 的 pass 物理保留在 `passes` 表里（`active=false`），之后每个阶段都要携带 active 判断——判断成本从"cull 时一次"摊销成"每阶段每元素一次"。旧版做法是逐级压缩，下游只遍历存在的行。

## 二、目标设计准则（提炼自两个参考，作为本轮验收口径）
1. **一类型一表**：image/buffer 各自成表，kind 编译期选表；运行时数据里不出现 kind 判别字段和 `std::variant`。
2. **存在性代替布尔**：不该处理的行就不在表里（cull 物理压缩、契约只存有契约的行、aliasing 候选只存可比行）；必须留的"无效"用语义哨兵（`invalid_pass` 等），不新增 bool 列。
3. **CSR 代替一切嵌套 vector**；handle 即稠密索引，**直接寻址数组代替哈希表**。
4. **两遍法**（计数 → 前缀和 → 散布）代替向嵌套容器 push_back。
5. **同构转换**：每阶段是对整列的 mutation / filter / emission；查重合并用排序+段内归并，不用逐元素线性扫。
6. **阶段纯化**：每阶段签名形如 `stage(const 输入表&, 输出表&)`；`compiler_state` 从可写聚合退化为阶段间只写一次的表集合。
7. **判断批量掩码化**：实在无法分区的判断（如 cache key 折叠），对整列无分支折叠。

### P2 — DAG CSR 化 + cull 图算法化（core 内部，无 ABI 变更）✅ 已完成（2026-08-13）
**目标：消灭嵌套 vector、哈希表、O(E²) 配对、O(P·E) 扫描。**
- `dependency_graph` 改 CSR：正向 `adjacency_list/adjacency_begins/in_degrees` + 反向 `rev_list/rev_begins`（一次建边同时产出，供 cull 反向遍历）。
- `build_dependency_dag`：利用 P1 双表——按 logical 计数排序分桶（计数→前缀和→散布，三趟无分支）；桶内按 pass 序维护 last_writer + 读窗口直接建边；边 (src,dst) 扁平追加后 sort+unique+前缀和成 CSR。O(E log E) 替代 O(E²·deg)。版本化建边只丢传递冗余边（A→B→C 存在时不再显式存 A→C）：可达性、cycle_detected 与 Kahn 输出逐 pass 不变（C 的入队时点由 B 决定，而 A 必先于 B 完成）——该等价性用 golden schedule 测试锁定，防止重建边时引入隐性差异。
- `schedule_passes`：改在 CSR 上跑 Kahn（保持最小堆确定性语义不变）。
- `cull_passes`：producer 表改为 `last_writer_image[]/last_writer_buffer[]` 直接寻址数组（一趟扫写事件列写入，无 `unordered_map`）；根标记 = 写事件列 × `is_imported` 列掩码 + backend_upload/side_effect 列；worklist 用扁平 vector（栈式 DFS 即可——活性闭包是不动点，遍历序不影响结果，不再用 `std::queue`）；沿 pass→reads CSR（P1 产出）查 last_writer，O(P+E)。
- 产出：紧凑 `active_pass_list` + `pass_old_to_new` 重映射列（本阶段先只用列表；压缩在 P3 落地）。
- 验证：全部单测绿（`culling_compile` 三场景是强契约）；微基准记录。
- **结果（2026-08-13）**：37/37 测试全绿，事件数保持 1531（语义不变）；`[bench] compile passes=256 events=1531 best_us=4833 median_us=5220`（Debug，较 P0 best -51% / median -52%，较 P1 best -26% / median -28%）。建边语义：每资源桶线性扫描维护 `last_writer` + 读窗口（读→last_writer 建 RAW 边并入窗口；写→last_writer 建 WAW 边 + 对窗口内全部读者建 WAR 边，随后清窗）——边集恰为 O(E²) 配对扫描的去传递冗余版（任一冲突对 (i,j) 要么直连要么经 i→w→j 可达），cycle_detected 与 Kahn 输出逐 pass 不变。cull 的 `unordered_map` 与 `std::queue` 已移除；`active_pass_list`/`pass_old_to_new` 已产出（P3 消费）。

### P4 — sync / submission SoA + CSR 化（**ABI 变更：`barrier.h`、`submission.h`**）✅ 已完成（2026-08-13）
**目标：消灭 AoS op、嵌套 vector、`valid` bool、op 复制。**
- `synchronization_op` 拆双 op 流：`image_sync_op_rows` / `buffer_sync_op_rows` 各自 SoA（phases/intents/logicals/physicals/memory_blocks/previous_logicals/passes/source_passes + before/after 的 usage_bits/accesses/domains/queues/ranges 列）——kind 列与消费端 kind 分支同步消失（后端 `emit_barriers` 本就按 image/buffer 分流 lowering）；scope 列删除（由 CSR 段位置隐含，lowering 不消费）。
- 生成改两遍法：第一遍对双事件表重放 last-state 链计数（count pass），前缀和得 `synchronization_segments.prologue_begins`（size = pass_count + 1），第二遍再重放散布直写列（scatter pass）——删除 `vector<vector<synchronization_op>> prologues` 与 `sync.ops` 混合流；internal 段删除（编译器从不发射 internal op）。
- `last_state.valid` bool 删除：`pass == invalid_pass` 哨兵编码"无先前用户"。
- handoff 的 O(H·E) 扫描改为重放中记录 first-access 事件行（`first_access` 列，O(1) 查）。

## 四、验收标准
1. 子仓 `render_graph.*` 全部单测绿（重点：`culling_compile` 三场景、`lifetime_aliasing`、`multi_queue`、`repeat_compile` 的 cache key 稳定性、`execute_context`）。
2. 架构契约测试绿（`core_layout`：公共头 ≤32KB、不暴露 `compiler_state`/`dependency_graph`、无 src-include 泄漏、core 不依赖 native API——`cmake/CoreLayoutContract.cmake` 现有检查项；另有独立的 `backend_ownership` 契约 `cmake/BackendOwnershipContract.cmake`，两契约均需保持绿；本轮不改契约内容）。
3. 主仓 `cglab.*` 单测绿 + GPU smoke（Triangle/GltfSponza 各 6 帧）通过。
4. 风格指标（grep 可验）：`src/core` 与公共头中无 `std::variant` 运行时分发、无 `std::vector<std::vector`、编译热路径无 `unordered_map`/`std::queue`；`compile_graph` 无早退链；`compiler_state` 各表由单一阶段写入（诊断 sink 除外——`fail()` 是各阶段共享的错误出口，属输出而非编译表）。
5. P0 微基准：compile 耗时不劣于基线（预期 256-pass 合成用例有数倍提升；以数据为准，不许凭感觉）。
## 五、风险与回退
- 每阶段一个独立提交单元，测试绿才推进；P3/P4 是仅有的 ABI 变更点，已确认影响封闭在子仓内。
- cache key 算法会变化：测试只约束稳定性/敏感性两条性质，允许；若外部有持久化 key 的假设需重新确认（当前未发现）。另注意 P3 物理压缩带来的语义变化：原实现被 cull 的 pass 仍参与 `plan.passes` 全量 hash（其声明改动会失效 key），压缩后"无影响的改动不再失效 key"——行为向正确方向收敛，`repeat_compile` 契约按新语义更新。
- cull 物理压缩改变 pass 索引语义：`source_passes` 列保留到 frame 行的映射供诊断；诊断里 pass 名的回填路径（`fail()` 中 `passes[pass].name`）随 P3 一并改列访问。
## 六、明确不做（本轮范围外）
- Vulkan backend 执行侧内部重构（`vk_runtime` 帧循环、`vk_resource_store` 等自身的 DoD 化）——本轮只改它们对编译输出的消费点。
- 层级 B：持久资源逻辑句柄化（`ArchitectureAndInternals.md:837-842`，ABI 级，未评估）。
- 物理多队列启用、`history` 资源执行语义、ray tracing 等 README 列的不支持项。
- 主仓还债清单项（`update_scene_transforms` 空 phase、`scene_registry` 胖 AoS 等，见 `docs/Architecture.md:79-87`）。
