依据：
- 第一轮准则（`docs/计划.md` §二）：#1 一类型一表 / kind 编译期选表；#2 存在性代替布尔；#3 CSR 代替嵌套 vector、handle 即稠密索引、直接寻址数组代替哈希表。

- 结论性分析：`typed_handle<Tag>` 本身（phantom type / newtype）是 DoD + 函数式风格的**正确实现**——tag 只存在于编译期，SoA 列布局与 `vector<uint32_t>` 逐位一致，零运行时开销；问题出在实现把 newtype 的四个闸门全部打开了，以及 `resource_handle` 把五个索引空间合并成一个类型。

## 一、现状评估（按严重度）

| # | 位置 | 问题 | 违背的原则 |
|---|------|------|-----------|
| 1 | `include/render_graph/resource.h:32` | 隐式 `operator uint32_t()`：typed handle 在任何 `uint32_t` 上下文静默脱标（索引、形参、赋值），newtype 防线形同虚设 | 函数式 "illegal states unrepresentable" 未达成 |

| 4 | `resource.h:46-93` | 与整数的 friend 比较/算术（`==/</<=/>/>=/+`）与 `operator++`：重新引入 "句柄就是 int" 心智（`pass < passes.size()` `system.cpp:59`）；`==` 双向而 `<` 单向，不对称；`operator+`/`++` 仅少数循环在用 | 哨兵纪律；P5 "删死代码" 精神 |
| 5 | `resource.h:376` `alias_handoff.kind` + `submission.h:39` `cross_queue_dependency.kind` | 编译产物里**最后两个运行时 kind 字段**，消费点做 `handoff.kind == image ? ... : ...` 分支（`system.cpp:1192/1272`）——正是 §1.2 #1 点名的模式 | 准则 #1；kind 判别应编译期选表 |

诚实说明：以上全部为零运行时开销问题（列布局不变、无分支、无分配），与第一轮 §1.3 口径一致——本轮动机是风格宪法一致性 + 类型保障，而非观测到的性能热点。

## 二、目标设计

### 2.1 硬化后的 `typed_handle`（P7a 目标形态）

```cpp
// Newtype over a dense 32-bit row index. The tag exists at compile time only:
// SoA columns stay plain uint32_t arrays with identical layout/cache behavior.
// Construction from a raw index is explicit and there is no implicit
// conversion back — image/buffer/pass index spaces cannot be mixed silently.
// The default value is the invalid sentinel ("data absence", not a flag).
template <typename Tag>
struct typed_handle
{
    uint32_t value = std::numeric_limits<uint32_t>::max();

    constexpr typed_handle() noexcept = default;
    explicit constexpr typed_handle(uint32_t index) noexcept : value(index) { }

    [[nodiscard]] constexpr uint32_t index() const noexcept { return value; }
    // Kept so existing `static_cast<uint32_t>(h)` call sites compile unchanged;
    // implicit decay stays forbidden.
    explicit constexpr operator uint32_t() const noexcept { return value; }

    // Same-space identity/order only; cross-space and integer comparisons
    // are ill-formed (no friend operators, no ++ / +).
    [[nodiscard]] constexpr auto operator<=>(const typed_handle&) const noexcept = default;
};
```

删除：隐式 `operator uint32_t()`（改 explicit）、`operator++`（前后缀）、`operator+`、全部 Integer friend。73 行收敛为约 18 行（`core_layout` 32KB 契约只受益）。

### 2.2 索引空间清单（P7b/P7c 目标形态）

| 索引空间 | 类型 | 哨兵 |
|----------|------|------|
| image 逻辑行 | `image_handle` | `invalid_image`（现有） |
| buffer 逻辑行 | `buffer_handle` | `invalid_buffer`（现有） |
| pass 行 | `pass_handle` | `invalid_pass`（现有） |
| submission batch 行 | `submission_batch_handle` | `invalid_submission_batch`（现有） |
| physical image 对象 | `physical_image_id`（新 tag） | `invalid_physical_image_id`（新增） |
| physical buffer 对象 | `physical_buffer_id`（新 tag） | `invalid_physical_buffer_id`（新增） |
| memory block | `memory_block_id`（新 tag） | `invalid_memory_block_id`（新增） |

不采纳的替代：每 kind 一个 `enum class : uint32_t`（每个索引/算术点都要 cast，与模板和哨兵组合不如 tag struct）；64 位胖句柄/位打包 kind（每条 SoA 列翻倍，与 DoD 相反）；运行时 kind 列（退回 P1 之前）。

## 三、分阶段实施

### P7a — `typed_handle` 硬化（无数据模型变更，纯编译期）

**目标**：关掉 §一 #1/#2/#4/#6 四个闸门；布局、数值、行为零变化。编译器报错驱动——隐式转换全部失效后，所有侵蚀点逐一显式化。

**改动点**：

1. `include/render_graph/resource.h:22-94`：按 §2.1 重写 `typed_handle`；`invalid_*` 常量保留（与默认哨兵值一致）。
2. 调用点手术（已知清单，按符号定位）：
   - 隐式构造/类型化循环（4 处）→ 裸 `uint32_t` 计数：
     - `graph.cpp:167`（schedule_passes 入堆初始化）：`for (uint32_t pass = 0; ...)` + `ready.push(pass_handle{pass})`；
     - `system.cpp:779`（cull worklist 播种）：`worklist.push_back(pass_handle{p})`；
     - `system.cpp:1383`（compile_submissions wait 边扫描）、`system.cpp:1511`（publish cache key 折叠）同理改计数。
   - friend 整数比较/算术（≈9 处）→ `.index()`：
     - `system.cpp:59` `pass < plan.passes.size()`；
     - `graph.cpp:123` `edge.to + 1`、`graph.cpp:176` `adjacency_begins[pass + 1]`；
     - `system.cpp:784/1100` `event_begins[pass + 1]`、`system.cpp:1386` `adjacency_begins[source + 1]`。
   - 隐式索引（≈20 处）→ `.index()`：
     - `graph.cpp:131/167/176/201`；`system.cpp:59/245/757/783/784/1100/1385/1386/1390/1391`；
     - `vulkan_device.cpp:706-771`（executor 循环头取 `const auto pass = pass_handle.index();`，列访问换 `pass`）；
     - `compiler_contract_test.cpp:267/340`。
   - `.value` 直取统一改 `.index()`：`system.cpp:1390/1391`、`system.cpp:1438-1440`。
   - 既有 `static_cast<uint32_t>(handle)` 站点（`system.cpp:232` 等）依赖 explicit 转换运算符继续原样编译，不动。
3. 本阶段**不**动任何列类型；`resource_handle` 别名保留。

**验证**：25/25 单测绿（尤其 `repeat_compile` cache key 稳定性——数值语义未变，必须逐字绿）；`compile_benchmark` 记录数据，预期与 P5 持平（布局零变化，以数据为准）；主仓 `cglab.*` + GPU smoke（Triangle/GltfSponzaSample 各 6 帧）。
**grep 验收**：`typed_handle` 定义无 Integer friend / `++` / `+`；全仓无 `for (pass_handle` 循环；无 typed handle 隐式索引（编译期已保证，grep 双检）。
**结果（2026-08）**：✅ 已提交 `96a1d83`。25/25 + 主仓 37/37 全绿，GPU smoke 通过；同机 A/B：P7a best 4329-4370µs / baseline 4244-4375µs（无差异，P5 记录值系环境噪声）。

## 五、风险与回退

- 每阶段一个独立提交单元，测试绿才推进；P7a 为纯编译期变化（零布局差），P7b/P7c 是仅有的 ABI 变更点，已确认影响封闭在子仓内。
- P7c 规模最大（核心 + 双后端 + 测试）。若单阶段过大，可将 `cross_queue_dependency` 拆分降级为 P7c 尾部可选项（该结构当前零后端消费，风险最低，也最可延后）。
- explicit 构造会引爆 `= {0, 1}` 类聚合初始化（集中在 tests），按编译错误清单逐项处理，无隐性风险。
- 语义不变保证：所有列仍为 4 字节、值逐位相同 → cache key、调度、aliasing 输出必须逐字不变；任何行为变化都视为本计划引入的 bug。

## 六、明确不做

- 运行时侧 `device_handle{index, generation}` 凭证模型不动（`render_device.h:27`，分层正确）。
- 输入侧 `frame_resource_handle` / `frame_resource_source` / frame 行不动（输入边界，kind 由双 span 位置表达，属调用者数据而非内部数据模型）。
- 编译侧句柄不加 generation、不做 64 位胖句柄、不做位打包 kind。
- 后端执行侧内部簿记的类型化（`vk_resource_store`/`vk_runtime`/`vk_bindless` 的 `uint32_t` 键与 `unordered_map` 键）——沿用第一轮"后端内部 DoD 化后置"边界。
- `compile_diagnostic` 的 `kind` + `resource` 字段保留（错误通道，非编译表；与 `fail()` 同属共享输出出口）。
- 层级 B（持久资源逻辑句柄化，`ArchitectureAndInternals.md:880-885`）不在本轮。
